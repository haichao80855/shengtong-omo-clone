## Problem Statement

教培行业综合业务系统（盛通教育 OMO 平台 `manage.shengtongedu.cn`）业务复杂度高，涵盖校区准入、学员生命周期、教研课包、教务课表调度与机构配置等庞杂链路。该生产系统存在以下痛点与复刻挑战：
1. **多 SPA 与技术栈老旧**：原系统采用分散的多独立 SPA（入口门户与管理子系统隔离）及已废弃的 Vue 2.6 + Webpack 技术栈，难以维护和现代化演进。
2. **黑盒逆向易破坏真实数据**：原系统运行在云端 WAF 和真实微服务网关后，包含敏感学员隐私信息（PII）。直接抓包或无节制测试极易触发账号封控或污染/破坏既有学员和排课生产数据。
3. **传统复刻脱节**：仅凭表面 UI 爬取无法还原深层业务状态机、表单正则校验及底层数据库实体关系，导致复刻出的系统空有外壳而无法支撑全栈真实业务闭环。

## Solution

建立一套标准化的 **“Playwright+HAR 流量录制 ➔ REA 静态 AST 逆向 ➔ AI 智能体 Schema-First 编码 ➔ 离线自动化测试差分比对”** 全栈复刻工作流：
1. **单仓架构归一化**：采用 pnpm Monorepo 整合为统一的 TypeScript 现代全栈工程（Vue 3 + Vite + Element Plus 前端，NestJS + Prisma + PostgreSQL 16 模块化单体后端，OpenAPI 3.0 共享契约）。
2. **安全无害化前置采集**：通过半自动 Headed 登录导出 Session，Playwright 路由拦截层实时执行 PII 正则脱敏；严禁在线写操作，所有增删改逻辑均通过前端 AST 逆向与离线沙箱推导。
3. **AST 辅助半白盒逆向**：使用 REA / Babel 解析线上 Webpack Bundle，直接提取 300+ 微服务 API、业务枚举字典和表单验证规则，沉淀为共享契约。
4. **单校区聚焦与离线黄金比对**：将复杂的多租户简化为确定性的单校区业务模型，在只读采集时同步沉淀 1920x1080 视觉黄金快照与 DOM 树，由 Playwright 离线回归套件完成像素级与交互级验收闭环。

## User Stories

### 门户与校区选择 (Portal & Choose)
1. As an 校区管理员, I want to 在访问系统根路径时自动进入校区选择门户页, so that 我能清晰查看当前被授权的管理校区。
2. As an 校区管理员, I want to 在校区卡片上直观看到校区名称、运营状态、详细地址与联系电话, so that 我能确认当前操作的物理校区实体。
3. As an 校区管理员, I want to 点击“进入工作台”按钮无缝切换至系统主管理后台, so that 我能开启日常综合管理业务。
4. As an 校区管理员, I want to 在门户页直接点击学员、教研、教务、机构管理等子系统卡片, so that 我能快速直达特定业务工作区。
5. As an 校区管理员, I want to 在系统全局顶栏查看当前激活的校区标签, so that 我在任何子模块下都能明确数据上下文归属。

### 工作台看板 (Dashboard)
6. As an 校区主管, I want to 在工作台顶部看到在读学员总数、开设课程数、本周排课次与可用教室数的统计卡片, so that 我能一目了然掌握校区核心运营指标。
7. As an 校区主管, I want to 在工作台查看近期的排课授课日程动态列表, so that 我能提前了解当天的上课班级、任课教师与场地占用情况。
8. As an 校区主管, I want to 在工作台通过快捷入口一键跳转至学员登记、排课调度等高频功能, so that 我能缩短日常操作路径。

### 学员全生命周期管理 (Student Management)
9. As an 教务老师, I want to 查阅学员档案列表并支持分页浏览, so that 我能管理校区的所有学员信息。
10. As an 教务老师, I want to 通过关键字（学员姓名或手机号）快速模糊检索学员, so that 我能在海量学员中秒级定位目标学生。
11. As an 教务老师, I want to 按照“全部/在读/结课/流失/潜在”状态 Tab 一键筛选学员列表, so that 我能分类处理不同生命周期的学生群体。
12. As an 教务老师, I want to 点击“新增学员”打开弹窗录入姓名、手机号、性别、状态和备注, so that 我能登记新招收的学生。
13. As an 教务老师, I want to 在输入手机号时触发正规的 11 位手机号格式校验与必填提示, so that 我录入的数据符合系统规范。
14. As an 教务老师, I want to 对既有学员进行档案信息编辑修改, so that 我能在学生联系方式或状态变动时保持信息准确。
15. As an 教务老师, I want to 在删除学员时触发二次确认危险警示弹窗, so that 我能避免误删学生档案造成数据遗失。
16. As an 教务老师, I want to 为学员办理课程报名，选择对应的校区售卖课程并绑定合同, so that 学员可以获得合法的上课资格与充值课时。
17. As an 教务老师, I want to 在学员报名时选择缴费支付方式（现金/转账/POS）并自动生成流水单据, so that 财务记录完整合规。
18. As an 财务/校区管理人员, I want to 查阅学员的电子钱包账户余额与充值、扣款流水, so that 我能掌握资金进出动态。
19. As an 教务老师, I want to 为学员办理“异动”操作（包括转班、休学、复学、退费）, so that 系统能够准确流转学员状态并记录异动日志。
20. As an 教务老师, I want to 下载学员批量导入的标准 Excel 模板, so that 我能按照固定格式准备大量历史学员数据。
21. As an 教务老师, I want to 上传填好的 Excel 文件执行批量导入，并能实时获取格式错误行与手机号重复的拦截提示, so that 批量导入的数据干净可靠。

### 教研与课程体系 (Research & Curriculum)
22. As an 教学教研主管, I want to 查阅校区开设的所有标准课程体系及所属科目分类树, so that 我能规范教学大纲和产品矩阵。
23. As an 教学教研主管, I want to 查看每门课程的标准建议价格、总课时数以及授课形式（班级课 / 一对一）, so that 我能核准课程的财务与教学规格。
24. As an 教学教研主管, I want to 新增标准化教研课程并配置课时和定价, so that 校区可以发布新的教学产品。
25. As an 教学教研主管, I want to 编辑已发布的课程参数, so that 在课纲升级或定价调整时保持业务同步。
26. As an 编程课教研老师, I want to 在编程素材库中分类浏览工程项目（Scratch、Python、课件讲义）, so that 我能获取教学所需的课件资源。
27. As an 编程课教研老师, I want to 上传本地编程素材工程包并进行类别标签归档, so that 资源库能够持续沉淀教学成果。

### 教务排课与课表调度 (Educational Affairs & Schedule)
28. As an 教务排课老师, I want to 基于教研课程包装并发布校区专属的“售卖课程”（配置实际售价、有效期和赠送课时）, so that 前台可以向家长销售该课包。
29. As an 教务排课老师, I want to 创建班级并为班级绑定售卖课程与任课老师, so that 学生可以统一分班进组。
30. As an 教务排课老师, I want to 在日历视图上排定班级课次，选择授课时间段与物理教室, so that 教学日程得到规范安排。
31. As an 教务排课老师, I want to 在排课冲突（同一教室或同一老师在相同时间段被重叠占用）时获得系统即时拦截提醒, so that 排课调度零冲突。
32. As an 任课教师, I want to 在上课前查看当天的课次日程动态并进入点名页面, so that 我能清楚当天上课任务。
33. As an 任课教师, I want to 在点名签到界面标记学员出勤状态（到课/请假/旷课）, so that 系统自动记录考勤日志。
34. As an 任课教师, I want to 在确认点名后触发系统自动课消，原子扣减到课学员对应课程的课时账户, so that 教学服务与课消消耗严格对应。
35. As an 任课教师, I want to 在课次结束后录入课堂评价与学员表现打分, so that 家长和教务可以追踪教学成果。

### 系统机构与场地管理 (Institution Management)
36. As an 校区管理员, I want to 查看和维护校区的基础资料（名称、对外电话、详细地址与营业状态）, so that 对外展示与合同主体信息保持规范。
37. As an 校区管理员, I want to 查看和管理校区下的教学场地与多媒体教室列表, so that 排课调度时有准确的物理资源池。
38. As an 校区管理员, I want to 查看教室的容纳人数与空闲状态, so that 班级编排时不会超过教室物理承载上限。
39. As an 校区管理员, I want to 系统默认具备基于角色的访问控制（RBAC）拦截，确保非授权用户无法越权修改系统与机构设置。

## Implementation Decisions

- **架构选型与单仓组织**：采用标准 pnpm Monorepo 统一大仓架构，彻底替代原系统的分散多 SPA 模式。前端置于前端应用工程，后端置于后端应用工程，接口契约定义统一固化在共享契约包中。
- **前端技术栈与组件映射**：前端基于 Vue 3 + Vite + TypeScript + Element Plus 构建，严格继承原系统的 Element UI DOM 语义、栅格布局与交互规范，避免重构带来的视觉断层。
- **后端架构与路由原生兼容**：后端采用 TypeScript + NestJS + Prisma ORM + PostgreSQL 16 模块化单体方案。为了让前端无感知兼容，后端显式保留原系统的微服务前缀映射（如 `st-front-student-server`, `st-education-server`, `st-research-server`, `st-manage-server`）。
- **单校区领域模型设计**：根据决策约束，后端全面采用单校区上下文（固定 `campus_id = 1`），免去多租户路由切换与跨库同步带来的过度工程开销。
- **数据流转与状态机闭环**：确立“标准教研课程 ➔ 校区售卖课包 ➔ 班级排课排班 ➔ 点名考勤与课消课评”的核心状态机流转闭环。
- **财务与第三方集成解耦**：
  - 支付结算：采用系统内账务流水记录（现金/转账/POS）与电子钱包虚拟余额管理，不接入外部银行/第三方支付清算网关。
  - 外部 SDK：呼叫中心（Clink 电话条）、直播客户端、外部商业地图统一采用高保真前端骨架与交互 Mock。
  - 文件处理：本地媒体目录存储持久化，Excel 批量导入基于 SheetJS/xlsx 服务端纯离线校验。
- **权限与播种数据**：
  - RBAC 角色权限模型，内置“校区超级管理员”开箱即用角色；
  - 数据库引入确定性种子脚本，初始化 1 所校区、5 间教室、10 门标准课程、20 名多状态在读学员及两周排课数据。

## Testing Decisions

- **测试接缝（Testing Seams）**：采用最高层级的一体化端到端黑盒接缝（Top-Level E2E System Seam）。所有自动化测试通过 Playwright 驱动真实无头浏览器，直接操作前端页面并断言最终网络请求、DOM 渲染与数据库真实持久化状态，杜绝测试内部易变实现细节。
- **离线黄金比对基准（Golden Visual & Data Baseline）**：在只读录制阶段沉淀 1920x1080 视口黄金标准截图与语义 DOM 树及 Fixtures 数据，在离线验收阶段通过 Pixelmatch 执行离线差分比对（视觉抗锯齿微差阈值控制在 5% 以内；DOM 与数据契约实行 100% 严格一致）。
- **契约级功能回归套件**：覆盖门户选择、看板指标、学员增删改查及生命周期异动、教研课程及素材、售卖课程与排课课消、机构场地配置全部 6 大核心业务场景。

## Out of Scope

1. **多租户/集团多校区跨库漫游**：当前规格聚焦于单校区（Campus ID = 1）深度闭环，不实现数百个多租户校区间的权限漫游与跨库分布式事务。
2. **三方外部真实硬件联调**：原系统外挂的容联七陌呼叫中心、腾讯地图定位、百家云直播 SDK 客户端不作全量真实联调，提供高保真前端占位与 Mock 通信交互。
3. **真实支付与银行渠道清算网关**：学员缴费与合同扣款仅在数据库内完成账户与课时数值变更，不接入微信/支付宝商户号直连清算网关。
